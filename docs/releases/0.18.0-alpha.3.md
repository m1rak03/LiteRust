# LiteRust 0.18.0-alpha.3

## Запуск

- Панель LiteRust загружается и становится видимой перед созданием WebView2 для первой страницы. Создание контроллера продолжает работать в потоке интерфейса согласно модели WebView2. Дополнительные окна получают уже созданное окружение того же профиля, когда это возможно. [Рекомендации Microsoft по запуску WebView2](https://learn.microsoft.com/microsoft-edge/webview2/concepts/performance)
- При штатном восстановлении корректный зашифрованный профиль загружается без повторной записи файла. При первом запуске, миграции прежнего формата, восстановлении из копии и сбросе сессии применяется обычное сохранение.
- Локальный startup.log содержит отметки запуска процесса и входа в Rust, открытия каталога профилей, проверки Runtime, загрузки настроек, создания окна, создания контроллеров интерфейса, показа панели, создания контроллера страницы и завершения первой навигации. Для приватного запуска используется private-startup.log. Времена измеряются в микросекундах от создания процесса, если Windows сообщает его время. Журнал этапов не содержит адресов или содержимого сайтов.

## Startup

- The LiteRust toolbar becomes visible before the first page's WebView2 controller is created. Controller creation follows WebView2's UI thread model. Additional windows reuse an environment from the same profile when available. [Microsoft's WebView2 startup guidance](https://learn.microsoft.com/microsoft-edge/webview2/concepts/performance)
- Normal session restore reads an existing sealed profile without rewriting it during startup. First startup, migration, restoration from backup, and a session reset still save the appropriate state.
- The local startup.log records the fixed startup phases, including process creation, Rust entry, settings, the WebView2 Runtime and controllers, the window, the visible toolbar and first completed navigation. Private startup uses private-startup.log. Timings use microseconds, relative to process creation when Windows supplies its timestamp.

## Замеры / Measurements

21 ноября 2026 года. Две Windows Debug-сборки с WebView2 Runtime 157.0.4341.60. Каждый вариант использовал собственный прогретый обычный профиль с новой вкладкой. После прогрева выполнено пять запусков на сборку по очереди. Внешний таймер фиксировал появление окна с готовой панелью и отдельно готовность документа новой вкладки. Опрос выполнялся примерно каждые 16 мс.

    ./tools/benchmark-startup-windows.ps1 -Baseline $OldExe -Candidate $NewExe

| Сборка | Панель, мс | Первая вкладка, мс |
| --- | --- | --- |
| 0.18.0-alpha.2 | 1366,6 (1358,3–1440,5) | 1397,1 (1391,4–1475,9) |
| 0.18.0-alpha.3 | 1094,6 (1084,3–1184,1) | 1460,3 (1396,0–1531,5) |

В таблице показана медиана и диапазон. Панель появилась раньше во всех пяти прогонах этого сценария. Первая вкладка по медиане открылась позже, а диапазоны времени загрузки пересеклись.
