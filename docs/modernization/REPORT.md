# LiteRust 0.16.0-alpha.1: отчёт о модернизации

## Реализовано

- Интегрированная верхняя панель обычного Tao-окна без отдельного системного заголовка. Кнопки закрытия, сворачивания, разворачивания/восстановления; native drag и двойной щелчок. Открытые края для штатного resize; координаты в logical units. Старый Borderless fullscreen и его shortcut удалены. Остальные назначения мигрируют без сброса.
- До 16 локальных профилей. Создание, переименование, открытие, собственное фото и стандартный аватар-инициал. Основной профиль использует прежний путь; новые — Profiles/<random-id>. Отдельные WebView2/Interface-v2, метаданные и VPN-конфигурация. Каталог профилей защищён DPAPI, блокировкой и резервной копией.
- Дополнительный закрытый профиль можно убрать после подтверждения; его данные перемещаются в ProfileTrash. Текущий/основной профиль не удаляется. Это восстановимое удаление, не безвозвратная очистка.
- Статус внешних аккаунтов — «неизвестен». Имена и аватары относятся к локальному профилю. Официальные ссылки сервисов сохранены; внешнее фото предлагается загрузить вручную.
- Шторка: по нажатию, hover с задержкой, закреплённая; скрытие, порядок, drag/drop и ширина. Временный режим сохраняет геометрию страницы. Z-order нативных child windows учитывается. Анимация 200 мс меняет только bounds панели; в покое её таймер отсутствует. Reduced motion и пользовательское отключение учитываются.
- Отдельные быстрые сайты: добавление, выбор из закладок, редактирование, удаление, перестановка; favicon напрямую с HTTPS-origin, без стороннего сервиса. Первая компоновка использует прежние закладки, не удаляя их.
- Редактор главной на 12-колоночной сетке: логотип, часы, дата, заголовок, подпись, поиск, сайты и почта/профиль. Перемещение, ширина (мышью или ползунком), скрытие/возврат, заголовки, отмена до 20 шагов, сброс и сохранение. На узком окне одна колонка. Сетка не допускает свободных пересечений и ухода за экран.
- Поиск с лупой и Enter использует единый Rust-обработчик адресов/запросов; поисковик не меняется. Темы, акцент, обои, собственные иконки и настройки анимаций сохранены.

## Архитектура и данные

Новые модули: `src/local_profiles.rs`, `src/home.rs`; интерфейс редактора — `ui/home-editor.js`. Модели панели находятся в `src/layout.rs`. Изменены `src/main.rs`, `src/storage.rs`, `src/newtab.rs`, `src/shortcuts.rs`, `src/windows_platform.rs`, `ui/toolbar.html`, `ui/dock.html`, `ui/start.html`.

Привилегированный IPC остаётся у toolbar/dock. У сайтов его нет. Команды главной идут через ограниченный внутренний URL; проверяются текущая внутренняя страница, tab ID, generation, действие, размер и модель. Текст экранируется, параметры сетки/ссылок валидируются. Настройка главной не пересоздаёт движок. Cookie-данные остаются под управлением WebView2.

Для основного профиля переноса каталогов не происходит. Старый BrowserData читается через serde defaults; прежний shortcut fullscreen удаляется отдельно. Закладки и история сохраняются. Новые параметры home/sidebar находятся в защищённых метаданных профиля. Аватары — в защищённом каталоге профилей; физическое хранение ещё не разнесено на отдельные файлы для каждого типа данных.

## Проверки

Локально: 64 Rust-теста; Windows x64 Clippy all-targets с `-D warnings`; статическая проверка исходников; UI-регрессии настроек, аккаунтов/инструментов, VPN, вкладок, горячих клавиш, окна, профилей, шторки и редактора; CSP/script injection проверки. Все перечисленные проверки прошли.

[Windows Actions 44175317509](https://github.com/m1rak03/LiteRust/actions/runs/44175317509): успешно. Проверены 65 тестов ядра, отсутствие отдельного заголовка по геометрии клиентской области, кнопки окна, горячие клавиши, отсутствие старого fullscreen, TUN и очистка маршрутов. Все шесть фаз синтетического теста cookies/localStorage/IndexedDB между запусками и двумя каталогами WebView2 прошли.

Полный установщик проверен при обновлении работающей 0.15.0-alpha.4: штатное закрытие, сохранение параметров и файлов профиля, DPAPI и резервные копии, совпадение установленного EXE со сборкой, ярлыки, запуск установленного браузера и удаление. Выпуск опубликован: EXE 252 144 558 байт, исходники и SHA256SUMS.txt.

Закрытие при обновлении выполняет нативный Rust helper (`tools/installer-close.rs`): он проверяет путь процесса и владельца окна, отправляет WM_CLOSE и ждёт завершения по дескриптору. Принудительное завершение не используется; PowerShell и компиляция C# для обновления не требуются. [Проверка 44175317714](https://github.com/m1rak03/LiteRust/actions/runs/44175317714) также подтвердила, что другая копия LiteRust из другого каталога остаётся работающей.

Ручная проверка на настоящей Windows: не выполнялась. Linux/Chromium-предпросмотр не считается проверкой Win32/WebView2.

## Производительность

Из очевидных лишних операций убрана повторная перестройка списков профилей, клавиш и панели при неизменившемся состоянии. Раскрытие шторки не меняет bounds страниц. Новые тяжёлые фреймворки/зависимости не добавлены.

Подготовлен `tools/benchmark-release-windows.ps1`: 0.15.0-alpha.4 и 0.16.0-alpha.1, по 3 независимых запуска, 5 приватных внутренних вкладок, по 3 замера. PrivateMiB — private committed memory, сумма Working Set дважды учитывает общие страницы. StartupReadyMs включает polling 200 мс, FourTabCommandsMs — искусственные паузы. Это ограниченный CI-сценарий, не измерение всех сайтов и не сравнение с Chrome/Edge. Методика учитывает время создания процессов: Windows повторно использует PID, поэтому одного родительского PID недостаточно для построения дерева. Ранние замеры без этой проверки исключены из выводов.

[Исходные данные успешного прогона](benchmarks/windows-44175317509.csv). Итог — медиана из трёх медиан запусков:

| Метрика | 0.15.0-alpha.4 | 0.16.0-alpha.1 |
| --- | ---: | ---: |
| Private committed memory, МиБ | 287,87 | 301,16 |
| Сумма working sets, МиБ | 497,23 | 516,44 |
| Процессы | 13 | 13 |
| Готовность интерфейса, мс | 707 | 672 |

В этом сценарии private committed memory выросла на 4,6%; снижение потребления памяти не достигнуто. Разница времени запуска 35 мс меньше шага polling и не доказывает ускорения. Порядок запусков и кэш могут влиять на результат. Измерения не являются тестом длительных утечек или произвольных сайтов.

## Ограничения и оставшиеся проверки

- Открытие другого профиля создаёт отдельное окно. Повторное открытие уже занятого профиля выдаёт ошибку блокировки; фокусировка существующего окна не реализована.
- Безвозвратная очистка архивированных профилей через UI и автоматическое восстановление каталога profiles.json из .bak не реализованы; повреждённый каталог не перезаписывается пустым.
- Нет OAuth-клиентов/официального доступа к внешним аватарам и достоверному статусу входа. Google может блокировать embedded WebView; ни вечная сессия, ни успешный вход не обещаются.
- Snap Layouts при hover над HTML-кнопкой не заявляется. Multi-monitor, DPI-переходы, drag/double-click/resize требуют ручной Windows-приёмки.
- Модель редактора — перестановка и ширина по сетке, не произвольные координаты X/Y. Шторка разворачивается в вертикальных положениях; верхнее/нижнее сохранены как компактные панели.
- Native overlay ещё требует визуальной проверки с разными сайтами/видео; favicon может отсутствовать или быть заблокирован сайтом.
- Замеры не доказывают отсутствие всех утечек. Реальные аккаунты и медицинский сайт не проверялись.
