# ПОЛНОЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ CODEX
## LiteRust Browser — комплексная модернизация

**Проект:** LiteRust Browser  
**Текущая версия:** 0.15-alpha.3  
**Язык:** Rust  
**Движок:** Microsoft Edge WebView2  
**Платформа:** Windows 10/11

# ГЛАВНАЯ ЦЕЛЬ

Комплексно модернизировать существующий LiteRust Browser, сохранив его архитектуру, функциональность, пользовательские данные и производительность.

Мне нужен современный браузер, который сможет стать полноценной альтернативой другим браузерам, но при этом будет лёгким, быстрым и максимально настраиваемым.

**Не создавай новый проект. Работай непосредственно с существующим исходным кодом.**

Сначала изучи проект целиком, его зависимости, структуру интерфейса, реализацию WebView2, систему вкладок, управление окнами и сохранение данных.

Не предполагай, что какой-либо механизм уже реализован правильно, пока не проверишь код.

# 1. ВЕРХНЯЯ ПАНЕЛЬ БРАУЗЕРА

Сейчас над вкладками присутствует отдельная системная строка Windows с надписью:

`LiteRust Browser 0.15-alpha.3`

Полностью убери эту отдельную системную полосу.

Реализуй интегрированную панель окна по аналогии с современными Chrome и Edge.

Требования:

- Вкладки должны находиться непосредственно у верхнего края окна.
- Отдельной полосы с названием и версией приложения быть не должно.
- Кнопки закрытия, сворачивания и разворачивания должны находиться справа.
- Окно должно перетаскиваться за свободное место верхней панели.
- Двойной щелчок по свободному месту должен разворачивать или восстанавливать окно.
- Должно работать изменение размеров окна за края и углы.
- Сохрани совместимость с Windows Snap Layouts, насколько это поддерживает используемый оконный фреймворк.
- Корректно обрабатывай масштабирование DPI и несколько мониторов.
- Не нарушай работу вкладок.

Используй корректные механизмы Win32 и существующей оконной библиотеки.

## Удаление ненужного полноэкранного режима

В браузере ранее был реализован отдельный полноэкранный режим.

**Найди и удали именно эту ранее созданную пользовательскую реализацию полноэкранного режима.**

Не нужно делать браузер настоящим fullscreen ради удаления заголовка окна.

Мне нужно обычное окно Windows, которое может разворачиваться на весь рабочий стол, сохраняя доступ к панели задач.

Не путай:
- Удаление системной строки заголовка.
- Стандартное разворачивание окна.
- Настоящий полноэкранный режим.

Сохрани стандартное разворачивание и сворачивание окна. Удали ненужные элементы управления и обработчики прежнего специального fullscreen.

# 2. ПОСТОЯННЫЕ ВЕБ-СЕССИИ

Реализуй правильное сохранение авторизации пользователей.

Поддерживаемые сервисы:

- Google.
- Яндекс.
- Microsoft.
- Yahoo.
- Другие сайты, работающие через WebView2.

Пользователь должен иметь возможность выполнить вход один раз и оставаться авторизованным после перезапуска браузера, пока сессия действительна.

Используй постоянные каталоги User Data Folder и поддерживаемые WebView2 механизмы профилей.

Корректно сохраняй:
- Cookies.
- Local Storage.
- IndexedDB.
- Другие необходимые данные веб-сайтов.

Не создавай новый временный профиль при каждом запуске.

Все вкладки одного веб-профиля должны использовать согласованное состояние авторизации.

Если пользователь выбирает Google как поисковую систему, поиск должен открываться с использованием соответствующей сохранённой сессии, если она действительна.

**Важно:** некоторые сервисы, включая Google, могут запрещать авторизацию внутри встроенных WebView. Не используй небезопасные обходы и не выдавай наличие cookies за подтверждённую авторизацию. Проверь реальные ограничения WebView2 и отчитайся о них.

# 3. ЛОКАЛЬНЫЕ ПРОФИЛИ LITERUST

Создай систему локальных профилей браузера без обязательной регистрации.

Мне не нужен собственный сервер, база пользователей в интернете или облачная инфраструктура.

Каждый локальный профиль должен иметь:

- Имя.
- Аватар.
- Закладки.
- Историю.
- Настройки.
- Выбранную поисковую систему.
- Персонализацию главной страницы.
- Собственный изолированный профиль веб-данных WebView2.

Добавь создание, переключение, переименование и удаление локальных профилей.

Не допускай смешивания веб-сессий между изолированными профилями.

При удалении профиля предупреждай пользователя о последствиях.

# 4. АВАТАР И СИСТЕМА АККАУНТОВ

В правой части главного интерфейса сейчас есть элементы «Почта» и «Аккаунты».

Замени отображение кнопки «Аккаунты» на круглый аватар выбранного локального профиля.

Пользователь должен иметь возможность:

- Установить собственную фотографию.
- Выбрать стандартный аватар.
- Использовать аватар Google.
- Использовать аватар Яндекса.
- Использовать аватар Microsoft.
- Использовать аватар других сервисов, если это официально поддерживается.

Необходимо позволить пользователю самостоятельно выбрать, какой аватар отображать.

Для получения внешнего аватара используй только разрешённые механизмы доступа. Если сервис не позволяет получить изображение, предложи загрузить его вручную.

При нажатии на аватар открывай меню:

- Текущий локальный профиль.
- Смена профиля.
- Изменение аватара.
- Подключённые веб-аккаунты.
- Управление аккаунтами.
- Настройки.

В меню аккаунтов отображай достоверное состояние авторизации: выполнен вход, не выполнен вход, необходим повторный вход или статус неизвестен.

Не показывай вымышленные имена, email и статусы.

Предусмотри возможность использовать несколько аккаунтов одного сервиса через изолированные веб-профили, если текущая архитектура это позволяет.

Всё должно работать без собственного сервера LiteRust.

# 5. ЛЕВАЯ ВЫДВИЖНАЯ ПАНЕЛЬ-ШТОРКА

Полностью переработай существующую левую панель браузера, сохранив её рабочие функции.

Мне нужна современная панель, которая плавно выдвигается справа от левого края.

## Свёрнутое состояние

- Узкая вертикальная панель шириной примерно 48–56 пикселей.
- Видны только иконки.
- При наведении отображаются подсказки.
- Панель занимает минимум пространства.

## Развёрнутое состояние

- Панель плавно раскрывается до ширины примерно 250–280 пикселей.
- Появляются названия разделов.
- Иконки остаются на прежних позициях.
- В верхней части находится кнопка сворачивания.
- Добавь плавную анимацию примерно 180–220 мс.

## Режимы

Реализуй три режима:

1. Открытие и закрытие по нажатию.
2. Автоматическое раскрытие при наведении с небольшой задержкой.
3. Постоянно закреплённая панель.

По умолчанию используй открытие по нажатию.

При временном раскрытии шторка накладывается на область страницы, а не постоянно уменьшает её ширину.

При закреплении панель занимает отдельное пространство.

## Разделы

Используй реально существующие функции браузера.

При наличии соответствующих функций предусмотрены:

- Главная.
- Закладки.
- История.
- Загрузки.
- Профили.
- Безопасность.
- Настройки.

Не создавай неработающие кнопки-заглушки.

## Настройка панели

Пользователь должен иметь возможность:

- Менять порядок иконок.
- Перетаскивать разделы.
- Скрывать ненужные кнопки.
- Возвращать скрытые кнопки.
- Изменять ширину закреплённой панели.
- Сбрасывать расположение.

Сохраняй настройки локально для каждого профиля.

**Особое внимание WebView2:** убедись, что панель корректно накладывается на содержимое браузера. Если используются нативные дочерние окна, учитывай ограничения их размещения и наложения.

Не пересоздавай WebView2 при открытии или закрытии шторки.

Не допускай перезагрузок страниц, мерцания и потери состояния вкладок.

- Перемещать их.
- Менять размер поддерживаемых виджетов.

- Изменять текст заголовков.
