## Воспроизводимая методика

Один компьютер/Windows build, питание и power plan, одинаковые viewport/DPI/zoom,
сайты, последовательность действий, аккаунты (только тестовые), согласия cookies,
кэш cold/warm и отсутствие расширений. Записать CPU/RAM/GPU, Chrome stable и
WebView2 версии, commit/версию LiteRust, auto_discard и бюджет 1/3/5.
Закрыть другие Chrome/WebView2 приложения, исключить общий профиль и фоновые задачи.
Порядок браузеров чередовать. После запуска/действий выдерживать одинаковый период.
Не сравнивать 20 живых Chrome страниц с 1 загруженной LiteRust как эквивалентную
работу: отдельно измерять auto_discard=false и каждый opt-in режим с учётом reload.

Для каждого основного сценария выполнить **минимум три независимых запуска**,
а не считать три соседних sample тремя повторами. Для каждого повтора собрать
12+ samples через 5 секунд. Сначала медиана samples внутри повтора, затем медиана
трёх повторов. Пример для повтора 1 (PID заменить фактическими корневыми PID):

```powershell
.\benchmark-memory-windows.ps1 -LiteRustProcessId 1234 -ChromeProcessId 5678 -Scenario '10-tabs-balanced' -Repeat 1 -Samples 12 -IntervalSeconds 5 -OutputPath run-1.csv
# После независимого перезапуска повторить с Repeat 2 и 3 / новыми PID.
python tools/summarize-benchmark.py run-1.csv run-2.csv run-3.csv
```

Скрипт суммирует дерево процессов и проверяет, что корневой PID не переиспользован.
`PrivateMiB` — private committed bytes, не фактически резидентная RAM.
`SumWorkingSetMiB` — сумма working sets, shared pages могут учитываться несколько
раз. Уникальная физическая RAM/shared memory не вычисляются: для этого нужны
ETW/WPA/VMMap или другой отдельный измеритель. Дерево по живым родителям может
пропустить осиротевший процесс; отдельно осмотреть остаточные msedgewebview2 после
закрытия. Не выдавать это за точное измерение всех уникальных физических страниц.

`CpuPercent` — delta CPU time процессов, присутствующих в двух соседних снимках,
делённая на wall time и число logical CPUs. Первый sample пустой. Короткоживущие
процессы/новые процессы не полностью учтены: при churn это нижняя оценка. Для
строгого CPU profiling использовать ETW, особенно сценарий открытия/закрытия.
Обновлённый PowerShell sampler в Windows **не выполнялся**; проверка формата
агрегатора на синтетическом CSV не является измерением браузеров.

Холодный/повторный запуск: ETW/WPR или видеозапись от запуска процесса до первого
полностью отображённого и интерактивного окна; отдельно до завершения загрузки
контрольной страницы. Process StartTime не равен готовности UI. Не смешивать
cold cache с cold OS boot. Idle 30 минут, видео фиксированного качества 10 минут,
leak test 2 часа + 100 циклов; сохранять timeline и остаточные процессы после exit.

Источники расходов: toolbar имеет собственную WebView; каждая живая вкладка
удерживает DOM/JS/renderer; переоткрытие выгруженной вкладки стоит CPU/network.
Low memory hint — рекомендация движку, не гарантия освобождения RAM. Фильтр
маленький, но его полезность и задержки CDP также нужно измерять.
