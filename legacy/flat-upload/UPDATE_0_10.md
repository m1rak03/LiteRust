# LiteRust 0.10.0-alpha.1 — проверка обновления

Дата: 2026-11-12. Исходник: предоставленный пользователем архив 0.9.0-alpha.1.

## Что изменено

- 5 вариантов оформления × 55 тем (11 палитр × 5 световых режимов); панель выбора с фильтрами и предпросмотром. Настройки проходят проверку диапазона в Rust, сохраняются в BrowserData; старые профили получают настройки по умолчанию. В приватном окне изменения не сохраняются.
- Темы применяются только к доверенной панели и внутренним страницам. IPC остаётся только у панели; внешним сайтам не добавлены привилегированные команды. Каталог цветов фиксированный, удалённые ресурсы не используются.
- ToolbarState больше не сериализует URL/back/forward каждой вкладки. JavaScript сохраняет DOM вкладок при обновлении загрузки/счётчиков, а CSS — при неизменной теме. Создание WebView больше не загружает стартовую страницу дважды.
- Ручная выгрузка фоновых WebView пропускает активную страницу, страницы в состоянии загрузки и вкладки со скачиваниями. Сохраняются URL и история; DOM, формы и медиа выгруженных вкладок теряются. Пользователь подтверждает действие. Автовыгрузка и режим Eco из исходной версии сохранены.
- К существующей кнопке Google Password Manager добавлен официальный портал аккаунта Google. Открытие фиксированных HTTPS-адресов осуществляется системным браузером без передачи пользовательских строк в shell. В приватном режиме команды запрещены. OAuth, синхронизация и Google-autofill не реализованы: у пользователя нет Client ID, API хранилища паролей не доступен для этой интеграции. Системный вход не авторизует WebView LiteRust.

## Выполненные проверки

- Rust core: 29 тестов; миграция, валидация и сериализация всех 275 сочетаний оформления, существующие проверки профиля/истории/импорта/URL.
- Clippy ядра и Windows all-targets с `-D warnings`.
- Rustfmt и статическая проверка JS/исходников.
- Chromium UI: все 275 сочетаний, фильтры (22 светлые / 11 контрастных тем), выбор/закрытие панели, команда Google, согласие/отмена ручной выгрузки, стабильность DOM вкладок, прежние тесты безопасности заголовков и поиска.
- Chromium: применение темы при загрузке и живое переключение стартовой страницы/библиотеки под CSP.
- Тест расчёта медианы Windows-бенчмарка на синтетических данных.

Логи текущей работы имеют префикс `audit-logs/current-`. Остальные логи и отчёты относятся к исходному архиву 0.9 и не являются новой проверкой.

## Ограничения проверки

Среда сборки — Linux. Windows/WebView2, вход в Google, скачивания, приватный режим и освобождение памяти не проверены реальным запуском на Windows. UI-тесты запускают HTML в Chromium, не само нативное приложение. Измерения ОЗУ до/после не проводились, поэтому нет подтверждённых MB/% экономии. Для такого измерения используйте `benchmark-memory-windows.ps1` на одних и тех же сайтах. Исполняемый файл не подписан цифровым сертификатом.

Для запуска нужен Windows x64 и Microsoft Edge WebView2 Runtime. Если Runtime отсутствует, установите его с https://developer.microsoft.com/microsoft-edge/webview2/ .

## Артефакты сборки

Собран Windows GNU release на Rust 1.99.1, MinGW-w64 GCC 12.2; формат проверен как PE32+ x86-64 Windows GUI. Браузер требует WebView2Loader.dll; она взята из x64-ресурсов зафиксированного crate webview2-com-sys 0.39.1. Сам WebView2 Runtime в комплект не входит.

- Единый EXE — запускатель с встроенными браузером и DLL (около 2.8 MiB). При запуске извлекает их в `%LOCALAPPDATA%\LiteRust\app\0.10.0-alpha.1-x64`, проверяет совпадение существующих байтов, запускает дочерний браузер и завершается. Параметры, включая `--private`, передаются браузеру. Скачивания, автозапуска, прав администратора и изменений реестра в запускателе нет.
- Portable ZIP — браузер и DLL рядом, плюс инструкция. Распакуйте все файлы, затем запускайте literust-browser.exe.
- Исходники включают `packaging/launcher.rs` и скрипт его сборки. Для самостоятельной сборки запускателя укажите пути к ранее собранному браузеру и x64 DLL.
- Извлечение/повторное использование/восстановление файлов запускателя проверено отдельным тестом на Linux. Импорты единого EXE содержат только системные Windows DLL. Это не заменяет запуск на настоящей Windows.
